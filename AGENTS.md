# AGENTS.md

MathBeast: a verified maths engine. Problems are generated by code, answers are
verified by code, the model only explains. `docs/design.md` is the architecture
(three primitives: Skill, Checker, Narrator); `docs/ui-roadmap.md` is the plan
for the web surface (P9–P20; P1–P8 are in `git log`).

## Install and test

```bash
pip install -e ".[dev,web]"
pytest -q          # the whole gate: no lint, no typecheck, no CI step beyond this
```

- The `web` extra is required for `tests/test_web.py` to run at all: it
  `importorskip`s FastAPI, so a `.[dev]`-only install silently skips the entire
  web surface. `python-multipart` in that extra is what makes every form POST
  work.
- `.[narrate]` is only for `mathbeast bench` (needs `requests`).
- Windows and macOS are tested deliberately (`.github/workflows/tests.yml`).
- Baseline: 700 passed, 15 skipped — or 701 passed with a capture supplied.
  14 skips are `test_packs.py` cases where the answer form makes leakage
  impossible; the 15th is the pixel harness with no capture supplied.
- Line length 100 (`[tool.ruff]`), but ruff is configured only — it is not
  installed and not run by CI.

## Pixel harness (`tests/test_capture.py`)

```bash
$env:MATHBEAST_CAPTURE='D:\Ibrahim106\Downloads\ChatGPT Image ....png'
python -m pytest tests/test_capture.py -q -s     # -s prints the delta report
```

- Skips unless `MATHBEAST_CAPTURE` is set or the file sits at repo root as
  `capture.png` (gitignored). Its deps are the `harness` extra
  (`.[harness]` — playwright, numpy, pillow), but installing it is only half:
  the browser binary is a second step, `playwright install chromium`. The extra
  is separate from `dev` because the harness is manual — the capture lives
  outside the repository, so CI has nothing to diff against.
- The capture is a **drawing**, not a screenshot: landmarks are compared, never
  per-pixel equality. Report every delta; write down the ones you deliberately
  leave standing instead of forcing them to zero.
- Two things the drawing cannot tell you, and P19 proved it: ink density and
  stroke contrast. Its title carries ~3× the ink of a 400-weight serif, so both
  are the tracer's pen. Choose faces on proportions only.
- Proportions quantize: at title sizes x-height and cap height are whole
  pixels, so a face's x/cap can move 0.03 for half a pixel of size. A face
  table measured at one size is a filter, not a verdict — measure at the size
  the page actually renders before believing a ratio.
- Use `python -m pytest`, not `rtk pytest`. The rtk wrapper in this environment
  swallows stdout, so `-s` never shows the report and a failing run looks
  identical to a passing one. If a command needs an env var and quoting keeps
  mangling it, put the whole thing in a `.ps1` under `D:\Temp\opencode\` and run
  it with `powershell -NoProfile -ExecutionPolicy Bypass -File`.

## Invariants (a wrong change here fails tests, not style)

- `sympy>=1.12` is a **trust boundary**, enforced at import in
  `mathbeast/__init__.py`. An older CAS computes differently; the guarantee
  degrades silently. The weekly `cas-canary.yml` runs against unpinned SymPy on
  purpose.
- Every skill clears six gates per seed in `tests/test_packs.py`; the
  load-bearing one is that the engine's answer verifies against the project's
  own checker under the skill's declared answer form.
- Skills are YAML and must never state a hardcoded `answer:` — the engine
  computes it.
- `mathbeast/web/static/tokens.css` is the **only** file permitted to hold a
  literal hex.
- No npm, no bundler, no CDN. Jinja, HTMX and SSE are vendored under
  `static/vendor/`.
- A control ships `disabled` until it has something real to do, and the comment
  beside it says what it is waiting for. The README table under "What the page
  does not claim yet" is **pinned by a test against the rendered page**, so a
  new disabled control fails the suite until its row is written — that test is
  the reason the comment and the README cannot drift apart.
- A number measured from the capture is exact; a number that was not measured
  says so in the comment where it is used.
- Comments explain *why*, especially where the obvious fix is the wrong one.
  Commit messages are prose paragraphs ending in the test count; phases are
  `P<n>: <title>`, one push each, app runnable after every one.

## Known traps

- New static file types (fonts, images, JSON) require adding a glob to
  `[tool.setuptools.package-data]` or the wheel ships without them. P19 chose
  not to vendor a face, so there is no font glob today — adding a webfont means
  adding one *and* deleting the test that pins the system stack.
- `test_web.py` pins exact orderings: tab stops
  (`test_the_home_surface_tabs_in_reading_order`, ~line 666) and
  `padding-bottom: 168px` on `.stage-main` (~line 1075). Renaming a control or
  moving a box breaks both by design.
- `mathbeast/_worker.py` runs the symbolic compare as a **separate
  interpreter**, not a thread: SymPy's `simplify` can hang, and a thread cannot
  be killed. Do not fold it back into a thread for speed.
- Templates share `_shell.html` / `_icons.html`; a change to a shared include
  lands on every page at once.

## Entry points

- CLI: `mathbeast` (`skills`, `coverage`, `drill`, `explain`, `bench`,
  `serve --port --model --ollama-url`), also `python -m mathbeast.cli`.
- App: `mathbeast.web.create_app(registry)`; `app = create_app()` at module
  level for uvicorn.
- Tests use `FakeBackend` — no network, no model, no Ollama required.
